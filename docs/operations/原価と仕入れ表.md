# 原価と仕入れ表（2026-10-26）

## 原価：レシート → 品目台帳 → メニューの原価

坂本さんの問い「取り込んだレシートで品目を分けてDBに記録 → ここから原価を割り出す、は機能している？」への答えと直したこと。

### 調べて分かったこと
- レシート → 品目台帳：動いていた（364品目・約404万円）。ただし品名の文字だけで品目を決めているので、道具・家具が食材に混ざっていた
  - ミルクパン（鍋）→牛乳、ホットサンドメーカー（COCOCAFE）→コーラ、カウンターチェア オリーブグリーン→オリーブ、塩ビパイプ→塩、
    おろしそば→大葉、製氷機→氷、エスプレッソマシンのクリーニングパウダー→コーヒー豆、抹茶セット（茶碗）→抹茶、パンプキンピューレ→パン
- 品目台帳 → メニューの原価：**つながっていなかった**。レシート保存時に仕入値を更新する仕組み（lib/menu.ts の updateCostsFromReceipt）はあったが、
  「フード材料費」などの区分の行しか見ておらず、区分が freee の勘定科目（仕入高・消耗品費）に変わってから一度も動いていなかった。
  動いていたとしても、行の合計（4個分）をそのまま1個の値段にしてしまう作りだった
- 注文メールの日付が「Sun, 4 Oct」の形で年が落ち、台帳の並び・購入間隔が狂っていた

### 直したこと
1. 品目の分け間違い：lib/freeeItems.ts の ITEM_RULES の先頭に、道具・家具を先に外すルールを足した（上の例はすべて正しい品目に）
2. メニューの材料を品目台帳の品目につなぐ（Ingredient.ledgerItem。無ければ材料名から自動で判定）
3. レシートを保存すると、行から「1個あたりの値段」を出して（lib/unitPrice.ts：単368・@698・4コ×・注文の個数）、つながっている材料の仕入値を更新する
   - 今の値段の半分未満・1.5倍超のときは自動では入れない（1パックの量が違う品の可能性）
4. 「メニュー → 原価の見直し」：材料ごとにレシピの仕入値と最近の買値（1個あたり）を並べ、「この値にする」「つなぎ先を変える」ができる
5. 注文メールの日付を YYYY-MM-DD に直した

### 残っていること
- レシピの「容量」が箱単位のもの（ジンジャーエール 30本など）と、買値が1本単位のものが混ざる。原価の見直しで1つずつ確かめる
- 食パンなどが勘定科目「消耗品費」で入っている（品目は正しい）。経理の科目の直しは別

## 仕入れ表：Googleスプレッドシート → Supabase
