# インスタの定期ストーリー（/instagram）

2026-11-03 作成。営業日の10時・19時のオープンのストーリーを上げ忘れることがあるので、自動で上げる仕組みを作った。ランニングなど毎週決まって上げるものも同じ画面で足せる。

## できること
- 定期ストーリーごとに、頻度（毎日・毎週・毎月・日を指定）と時刻と画像を決める。1つの時刻に画像を複数入れると順に上げる
- 「営業日だけ」にすると、定休日（火曜・`lib/shop.ts`）と画面で入れた臨時休業の日は出さない
- 「手で上げていたら出さない」：時刻の60分前（変えられる）〜30分後の間に手でストーリーを上げていれば、自動の分は出さない。自動で上げた分は数えないので、同じ10時に2つの決まりがあっても両方出る
- 5分おきの cron（`/api/cron/instagram`）が 7:00〜22:55 だけ動く（UTCで `0-13,22-23` 時）。時刻は7:00〜22:30の間しか保存できない。時刻を30分過ぎたら、その回はもう出さない（昼に朝の分が出るのを防ぐ）
- 失敗したら履歴に理由が残り、30分の間は次の cron でもう一度試す

## できないこと
- APIからはスタンプ（リンク・メンション・場所・音楽・アンケート）を付けられない。文字は画像に入れておく
- 画像はJPEGだけ。画面で写真を選ぶと幅1080のJPEGに直してから保存する

## 仕組みのメモ
- 保存は KV：`ig:rules`（決まり）・`ig:images`（画像の一覧）・`ig:closures`（臨時休業）・`ig:conn`（接続）・`ig:runs`（直近200件の履歴）
- 画像本体は非公開の Blob（`ig/img/<32桁>`）。インスタのサーバーが取りに来るので、`/api/instagram/img/<id>.jpg` だけ合言葉なしで開ける（middleware）
- 「手で上げたか」は `/{ig-user-id}/stories`（いま出ているストーリー）の timestamp で見る。このAPIがインスタログインのトークンで使えるかはMetaの説明に書かれておらず、取れなかったときは**上げる方に倒す**（上げ忘れの方が困るため）。履歴に「確かめられなかった」と出たら、この判定が効いていない
- 計算は `lib/instagramPlan.ts`（テスト `lib/instagramPlan.test.ts`）、APIと保存は `lib/instagram.ts`
