# 経理データを Supabase に入れる Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** freee のデータを5分おきに Supabase に写し、経理画面・明細の画面・LINE のリマインド・未払金・月次レポートを Supabase から出す。

**Architecture:** freee から読む処理を「データの取り出し口」（`FreeeSource`）にまとめ、freee から直接読む口（`live.ts`）と Supabase から読む口（`read.ts`）を同じ形にする。取り込み（`sync.ts`）は live で取って Supabase に書く。画面の API は `pickSource()` で口を選ぶ（Supabase に一度でも取り込めていれば Supabase、まだなら freee、`?source=freee` なら freee）。照合と損益の計算（`lib/keiri/*`）は変えない。

**Tech Stack:** Next.js 15.5（App Router、`after()`）、React 19、TypeScript、styled-jsx、`@supabase/supabase-js` v2（新規）、Vercel KV（鍵）、Vercel Cron、freee 会計 API（`lib/freee.ts`）。テストは Node 24 の `node --test`。

**Spec:** `docs/superpowers/specs/2026-10-16-keiri-db-design.md`

## Global Constraints

- Supabase にはサーバーからだけつなぐ。環境変数は `SUPABASE_URL` と `SUPABASE_SECRET_KEY`（`sb_secret_...`）。`NEXT_PUBLIC_` を付けない。表はすべて RLS を有効にし、ポリシーは作らない
- Supabase の地域は **East US (North Virginia)**。本番の関数が iad1 で動いているため（2026-10-16 に `x-vercel-id: kix1::iad1::…` で確認）。設計書の「東京」から変更
- すべての表に `company_id`（今は `12575763` = `FREEE_COMPANY_ID`）
- freee の応答は形を変えずに `raw`（jsonb）に入れる。`lib/keiri/cashflow.ts`・`pl.ts`・`linkReceipts.ts`・`sheet.ts` は変えない
- 会計年度は 6/1〜翌5/31（`lib/keiri/period.ts` の `FISCAL_START_MONTH = 6`）
- 取り込みの鍵: KV `freee:sync-lock`（120秒）、もう1回の印: KV `freee:sync-again`、接続の鍵の更新: KV `freee:refresh-lock`（20秒、待つ側は500ms×20回）
- 古いとみなすのは最後の成功から **15分**。LINE で知らせるのは最後の成功から **60分**、失敗が続いている間に1回だけ
- 毎晩の取り込みは JST 3時以降の最初の回（その日にまだやっていなければ）
- `lib/freeeMirror/` と `lib/keiri/` の純粋な関数は、実行時に他のファイルを import しない（型は `import type`、Node の組み込み `node:crypto` は可）。テストから `.ts` 付きで読むため
- 画面の文言はすべて日本語。時刻は JST で `10/16 10:35`
- dev server は立てない。確かめは `npm test` と `npm run build`、最後に本番
- コミットは `sync` ブランチ。`main` への反映は坂本さんが「main に反映」と言ってから

## Review Focus

- freee の取り込みが途中で失敗した（429・タイムアウト・接続切れ）→ Supabase は1行も書き換えず、画面は前の数字のまま「取り込めていません」を出す（Task 4 で「全部取り切ってから書く」順にする。Task 1 の `isStale` テスト）
- freee との接続が切れたまま1時間たつ → LINE は1回だけ。5分ごとに何通も来ない（Task 1 の `shouldAlert` テスト）
- 鍵の期限が近いときに、月次の6本同時の読み込みと取り込みが重なる → 更新は1回だけ、全員が新しい鍵で続ける（Task 2 の `accessTokenWithLock` テスト）
- Supabase の表が1000行を超える（取引は今期の終わりに2000件ほど）→ 全部読める（Task 3 の `readAll` テスト）
- Supabase の環境変数が無い・まだ一度も取り込めていない → 画面は今までどおり freee から出て、エラーにならない（Task 5 の `pickSource`、Task 7 で確認）

```ts
const NOW = 1_800_000_000;
const tick = () => new Promise<void>((r) => setImmediate(r));
function deps(initial: Tokens | null) {
  const kv = fakeKv();
  let stored = initial;
  let calls = 0;
  const d: RefreshDeps = {
    kv,
    load: async () => stored,
    save: async (t) => { stored = t; },
    refresh: async (rt) => { calls++; await tick(); return { access_token: `new-${rt}`, refresh_token: "r2", expires_at: NOW + 21600 }; },
    nowSec: () => NOW,
    sleep: tick,
    notConnected: () => new Error("freee未接続です"),
  };
  return { d, calls: () => calls, kv };
}

test("期限に余裕があれば、更新しない", async () => {

test("期限が近いときに6本同時に呼んでも、更新は1回で、全員が新しい鍵を使う", async () => {
```

- [ ] **Step 3: 実装する**

`accessTokenWithLock` の流れ（期限の判定は今と同じ `expires_at - 60 > nowSec()` で「まだ使える」）:

```
t = load(); 無ければ notConnected()
まだ使える → t.access_token
token = tryLock(kv, REFRESH_LOCK, 20)
取れた → try { t2 = load(); まだ使える → t2.access_token; nt = refresh(t2.refresh_token); save(nt); nt.access_token } finally unlock
取れない → 20回まで { sleep(500); t3 = load(); まだ使える → t3.access_token }
         → throw Error("freeeの接続の更新を待ちきれませんでした")
```

`lib/freee.ts` の `getAccessToken` は、KV が無ければ今と同じく `FreeeNotConnected`、あれば `accessTokenWithLock({ kv: store, load: loadTokens, save: saveTokens, refresh: (rt) => tokenRequest({ grant_type: "refresh_token", client_id, client_secret, refresh_token: rt }), nowSec, sleep, notConnected: () => new FreeeNotConnected() })` を返す。`lib/freee.ts` からは `@/lib/freeeMirror/refresh` と `@/lib/freeeMirror/lock` を拡張子なしで import する。


```ts
function syncAfterResponse() {
  try {
    after(async () => {
      const { syncFreee } = await import("@/lib/freeeMirror/sync");
      await syncFreee("after-write");
    });
  } catch {
    // リクエストの外（スクリプトなど）では after が使えない。取り込みは次の cron に任せる

}
```

## 設計書からの変更

- Supabase の地域: 東京 → East US (North Virginia)（本番の関数が iad1 のため）
- 途中で失敗したとき: 「失敗した表だけ書かない」→「全部取り切ってから書く。1つでも失敗したら何も書かない」（数字が月の中で食い違わないように）
- `?source=freee` は比較のために残す（freee から直接読む口は取り込みが使うので、消すコードは無い）。比較はスクリプト（`scripts/compare-keiri-db.ts`）ではなく、この引数を使ってブラウザで行う（秘密の鍵を手元に置かずに済む）
- 取り込みの状態は1行の表 `freee_sync_state` に置く（最終成功・エラー・LINE を送った時刻・毎晩の日付・月ごとのハッシュ）
