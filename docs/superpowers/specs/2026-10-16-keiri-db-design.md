# 経理データを Supabase に入れる 設計書

2026-10-16 / 依頼: 坂本さん

## 目的

経理の画面を開くたびに freee を読みに行くのをやめる。freee のデータを5分おきに Supabase に取り込み、画面と LINE は Supabase から読む。

今の困りごと（坂本さん）: 「表示が遅いし、freee がログアウトすると見れない」

成功の条件:

- 経理画面（月次）が freee を待たずに開く
- freee との接続が切れても、経理画面・明細の画面・LINE のリマインドに、最後に取り込んだ数字が取り込み時刻つきで出る
- freee で処理した内容は5分以内に画面に出る。システムから freee に登録した内容は、登録の直後に取り込み直す
- 数字が今の画面と変わらない（同じ月で、Supabase から出した結果と freee から直接出した結果が一致する）

## 決まったこと（坂本さんの回答）

| 論点 | 決定 |
|---|---|
| データベース | Supabase（ABC と同じ）。flat 用のアカウントを新しく作る |
| 反映の早さ | 数分おきに自動で取り込む → 5分おき |
| 範囲 | freee を読むだけの画面をまとめて Supabase から出す（経理画面、明細の画面、LINE のリマインド、未払金、月次レポート、AI チャット） |
| 経理スケジュール | 別の設計書にする。この DB 化のあとに作る |

## 置いた前提

- 正しいのは freee。Supabase は写しで、システムからは書き換えない
- freee への登録（取引・仕訳・消込など）は、これまでどおり freee に直接書き込む
- freee の API の応答を、形を変えずに保存する（`raw` 列、jsonb）。照合と損益の計算（`buildCash`、`buildPl`、`attachReceipts`、`buildMonthly`）は変えない。変えるのは読む先だけ
- レシートの画像、立替の記録、行の色とメモ、経理メモは今の KV のまま（freee のデータではない）。他社に広げるときに Supabase へ移す
- どの表にも `company_id` を持たせる（他社に広げるため）。今は flat（12575763）だけ
- Supabase にはサーバーからだけつなぐ。サーバー用の秘密の鍵は Vercel の環境変数に置き、ブラウザには出さない。表は RLS を有効にしてポリシーを作らない（公開用の鍵では読めない）
- Vercel の契約は毎時の cron が動いているので Pro。5分おきの cron を置ける

## 1. 表

| 表 | 主キー | 中身 | 検索に使う列 |
|---|---|---|---|
| `freee_wallet_txns` | `company_id, id` | 口座の明細（銀行・カード・現金など全口座） | `walletable_type`, `walletable_id`, `date`, `status` |
| `freee_deals` | `company_id, id` | 取引（支払い・入金の記録を含む） | `issue_date` |
| `freee_manual_journals` | `company_id, id` | 振替伝票 | `issue_date` |
| `freee_transfers` | `company_id, id` | 口座振替 | `date` |
| `freee_masters` | `company_id, kind` | 一覧（`walletables`・`account_items`・`partners`）。1行に一覧まるごと | — |
| `freee_reports` | `company_id, kind, period` | 試算表。`trial_pl` は月ごと（`period` = `2026-10`）、`trial_bs_partner` は年度ごと（`period` = `fy2026`、取引先の内訳つき） | — |
| `freee_sync_runs` | `id` | 取り込みの記録（始まり・終わり・成否・エラー・リクエスト数・件数・きっかけ） | `started_at` |

どの表にも `synced_at`（取り込んだ時刻）を持たせる。

試算表は `breakdown_display_type=partner` を付けると、取引先ごとの残高が1回で返る（2026-10-16 に確認）。未払金の画面は今、取引先ごとに1回ずつ freee に聞いているので、これで1回になる。

## 2. 取り込み

`lib/keiri/sync.ts` の `syncFreee(trigger)` が1回分を行う。

### 毎回（5分おき）取り込むもの

- 一覧3つ（口座・勘定科目・取引先）
- 今期（会計期間の初日〜今日）の明細（全口座）、取引、振替伝票、口座振替
- 貸借の試算表（今期、取引先の内訳つき）
- 損益の試算表は、今月と先月。それに加えて、その月の取引・振替伝票・口座振替が前回の取り込みから変わった月（月ごとに行の中身のハッシュを取り、前回の取り込みの記録と比べる）

### 毎晩（3時）取り込むもの

- 今期の全月の損益の試算表
- 2期目に入ったら、前期の分（決算の修正を拾うため）

### 書き込み方

- 表ごとに、freee から最後のページまで取り切ってから書く。途中で失敗した表は書かない（古いまま残す）
- 取り込んだ行は `id` で上書きする。取り込んだ範囲にあって今回 freee から来なかった行は消す（freee で消された分）
- Supabase は1回で1000行までしか返さないので、読むときもページを分ける

### 同時に動かさない

- 取り込みは KV の鍵（`freee:sync-lock`、2分で自然に外れる）で1つずつにする。動いている最中に頼まれたら「もう1回」の印を付け、終わったあとにもう1回だけ回す
- freee との接続の鍵の更新（`lib/freee.ts` の `getAccessToken`）も KV の鍵で1つずつにする。freee は更新のたびに鍵が新しくなるので、今のように並べて呼ぶ処理（月次は6本同時）が同時に更新すると、古い鍵での更新が失敗する。更新を待った側は、保存された新しい鍵を読み直して使う

### きっかけ

| きっかけ | 動き |
|---|---|
| cron（`*/5 * * * *`、`/api/cron/freee-sync`） | 取り込む。鍵がかかっていたら何もしない |
| cron 毎晩3時 | 毎晩の分も含めて取り込む |
| システムから freee に登録した | `freeePost`・`freeePut`・`freeeDelete` が成功したら、応答を返したあとに取り込む（Next.js の `after()`）。登録する側のコードは変えない |
| 経理画面の「今すぐ取り込む」 | 取り込みが終わるまで待って、画面を読み直す |

### 失敗したとき

- `freee_sync_runs` にエラーを残す
- 最後に成功してから1時間たっても成功しなければ、LINE で坂本さんに1回だけ知らせる（「freee から取り込めていません。再接続してください」と接続のリンク）。成功したら印を消す
- freee のリクエスト数の上限（1事業所あたり1分に約120回と言われている）を超えたとき（429）は、少し待ってやり直す。1回の取り込みは今期の終わりでも50回ほどの見込み。リクエスト数は `freee_sync_runs` に残して確かめる

## 3. 読む側

`lib/keiri/store.ts` に読む関数を置く。返す形は freee の応答と同じにする。

| 画面・処理 | 今 | これから |
|---|---|---|
| 経理画面（`/api/keiri/monthly`） | freee から6種類を読む | Supabase から読む。「最終取り込み」の時刻を返す |
| 明細の画面（`/api/freee/unprocessed`） | 全口座の明細を freee から読む | Supabase から、未処理（`status = 1`）の明細を読む |
| カードとレシートの照合候補（`/api/freee/match-card-receipts` の GET） | freee から読む | Supabase から読む。登録（POST）は freee に書く |
| LINE のリマインド（`keiri-remind`） | 明細の画面の API を呼ぶ | 同じ（明細の画面が Supabase から読むので、そのまま切り替わる） |
| 未払金（`lib/payables.ts`） | 取引先ごとに試算表を読む | Supabase の `trial_bs_partner` から読む |
| 月次レポート・AI チャット（`lib/monthlyReport.ts`） | 取引と振替伝票を freee から読む | Supabase から読む |

`/api/freee/deals`・`/api/freee/wallet-txns` など、freee に書き込む処理のための読み込みは、今回は変えない。

## 4. 画面

- 経理画面の上に「最終取り込み 10/16 10:35」と「今すぐ取り込む」ボタンを出す。明細の画面にも時刻を出す
- 最後の成功から15分以上たっていたら、黄色の帯で「freee から取り込めていません（最終 10:35）」と出す。接続が切れているときは「freee に接続する」のリンクも出す。数字は最後に取り込んだもので出し続ける
- 読み込み中の文言を「freeeから読み込んでいます…」から「読み込んでいます…」に変える

## 5. 切り替えの順番

1. 坂本さん: flat のメールで Supabase に登録し、プロジェクトを作る（地域は東京）。接続用の値を Vercel の環境変数に入れる（手順は別に案内する）
2. 表を作る（`supabase/migrations/` に SQL を置く）
3. 取り込みと cron を入れて本番に出し、表が埋まるのを待つ
4. 2026-08・09・10 の3か月で、Supabase から出した結果と freee から直接出した結果（経理で見る・会計で見る・未処理の明細・未払金）を比べ、一致を確かめる
5. 読む先を Supabase に切り替える。確かめが済んだら、freee を直接読んでいたコードを消す

main への反映は、坂本さんが「main に反映」と言ってから。

## 6. 確かめ方

- `node --test` で確かめる純粋な部分: 消された行の見つけ方、試算表を取り直す月の選び方、ページ分け、鍵の取り合い（KV は偽物を使う）
- `npm run build` が通る
- 切り替えの順番4の比較を、スクリプト（`scripts/compare-keiri-db.ts`）で行う
