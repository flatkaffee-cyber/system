# 月次の結果を1つにそろえ、「全体・店舗だけ・イベント」で切り替える 設計書

2026-10-18 / 依頼: 坂本さん

## 目的

経理画面の月次（`/keiri`）と月次レポート（`/monthly`）で、9月の結果が +¥418,715 と −¥238,401 のように違って見える。前者はお金の出入り、後者は損益に見込みを足したもので、測っているものが違うためだが、見る人は混乱する。

両方の画面で同じ「結果」が見えるようにし、経理画面では「全体・店舗だけ・イベント」で切り替えられるようにする。

成功の条件:

- 同じ月の「店舗」「イベント」「臨時」「全体」の4つの数字が、経理画面と月次レポートで1円も違わない
- 経理画面の月次の上で「全体・店舗だけ・イベント」を選ぶと、上の数字と下の表がいっしょに切り替わる
- 「全体」には、クラファンや補助金のような一度きりの収入が入る（帳簿の上で前受金のものも入る）

## 決まったこと（坂本さんの回答）

| 論点 | 決定 |
|---|---|
| 何をそろえるか | 2つの画面で同じ結果を見せる |
| 切り替え | 全体・店舗だけ・イベントの3つ |
| 全体に入るもの | 店舗とイベントに、臨時の収入（クラファン・補助金など）と一度きりの支出を足したもの |
| 見本 | 2026-10-18 の見本（上に切り替え、4つのカード、表に区分の列）で進める |
| 利益にならない大きな出金 | 内装工事の残り・備品の購入・借入の返済などは「全体の結果」に入れない（2026-10-19）。借入の入金も収入に入れない。表では「臨時」の札で出し、「店舗だけ」には混ぜない |

## 置いた前提（私の判断）

- 数え方は今の月次レポートに合わせる。売れた月・使った月で数え（freee の取引と振替伝票の計上日）、毎月かかるのに freee にまだ入っていない費用（社会保険料・國仲さんの業務委託料など、月次レポートの設定の「見込み」）を引く。イベント日の Square の売上は、今と同じく通常営業からイベントへ移す
- 計算は1か所にする。`lib/monthlyReport.ts` の `buildMonthly` が出す結果を、両方の画面が使う
- 「臨時」には、今の月次レポートの「臨時」（雑収入・受取利息・返金・一度きりのタグの付いた支出など、振り分けの決まりは今のまま）に、前受金の入金（今は欄外に出しているクラファンの入金）を足す
- 「全体」= 店舗 + イベント + 臨時。月次レポートの③「この月の成績」も同じ数字にする（今は前受金を含まないので、ここだけ数字が変わる）
- 臨時は切り替えの選択肢にはしない（坂本さんが挙げたのは3つ）。全体のときにカードで見える
- 振り分けの付け替え（月次レポートの行ごとの「通常・イベント・臨時」の選択）は今の保存先をそのまま使い、両方の画面で同じものが効く
- 前受金は、入金を臨時の「+」、売上への振り替え（取り崩し）と返金を臨時の「−」として数える。クラファンなどの前受金を売上に振り替える振替伝票の売上の行は、自動で臨時に振り分ける。こうすると、入金の月に全体に入れた分が振り替えの月にもう一度数えられず、店舗の数字も膨らまない（クラファン以外の前受金も同じ扱い）
- 「経理で見る」の表には見込みの費用を出さない（表は実際に動いたお金だけ）。見込みはカードと「会計で見る」にだけ出る。2026-10-18 の見本の表には見込みの行があったが、ここは見本と変える

## 1. 計算（`buildMonthly`）

返す値に次を足す。

```
scopes: {
  store: 店舗の結果（今の regular.profit）
  event: イベントの結果（今の event.total）
  irregular: 臨時の結果（今の irregular.total + 前受金の入金の合計）
  total: store + event + irregular
}
```

`final` は `scopes.total` と同じ値にする（月次レポートの③）。前受金の行（`offBook`）は今のまま一覧でも返す。

イベント日の Square の売上を移すには Square の売上の取得（今は `/api/monthly-report` の中で `/api/analytics` を呼んでいる）が要る。これを関数にして、経理画面の API からも同じものを使う。

## 2. 経理画面の月次（`/keiri`）

### 上の部分

- 月の見出しの右に、切り替え「全体・店舗だけ・イベント」を置く。選んだものは URL（`scope=all|store|event`、既定は `all`）に持つ
- その下に4つのカード: 店舗（通常営業）／イベント／臨時（一度きりの収入・支出。クラファンの入金があれば「クラファン入金 +¥… を含む」と小さく出す）／全体の結果
- 選んでいる範囲のカードを強調する（全体なら「全体の結果」、店舗だけなら「店舗」）
- 今の上のカード（入金・出金・差引・領収書なし・未処理）は、領収書なしと未処理の件数だけ残し、表の上の道具の帯の近くに小さく出す。入金・出金の合計は表の区切りの小計で見える

### 経理で見る（お金の出入りの表）

- 表に「区分」の列（店舗・イベント・臨時の色付きの札）を足す
- 区分の決め方:
  - 取引・振替伝票に結びついた行は、月次レポートのその取引の行の区分（取引に区分の違う明細が混ざるときは、金額の大きい明細の区分）
  - 前受金の入金の行は臨時
  - 取引・振替伝票に結びつくが、月次レポートに行が無い行（損益に出てこない動き。内装工事・備品・借入と返済・役員との貸し借りなど）は臨時。カードの数字には入らない
  - 取引に結びつかない行（Square・PayPay の入金、口座振替、突き合わせできなかった行）は店舗
  - どの行も、区分の札を押して付け替えられる。取引・振替伝票に結びつく行は、その取引のすべての明細の区分を月次レポートと同じ鍵（`deal:{id}:{明細番号}` など）で付け替えるので、カードと月次レポートの数字も動く。計上日が前の月の取引なら、動くのはその月の数字（札を付け替えたときに一言出す）
  - Square・PayPay の入金や口座振替など、損益に出てこない行の付け替えは、表の札だけに効く（行の印 `row:w123` などで同じ保存先に残す）
- 「店舗だけ」「イベント」を選ぶと、その区分の行だけ出す。区切りの小計もその行だけで出す
- Square の入金にはイベントの日のレジ売上も混ざっているが、入金は分けられないので店舗の行のまま。そのぶん、イベントのカードの数字と、イベントで絞った表の入金の合計は一致しない。表の上に「イベントのレジ売上は Square の入金に含まれるため、この表では店舗に入っています」と一行出す

### 会計で見る（損益計算書）

- 全体: 今の損益計算書（freee の試算表）の下に、「見込みの費用（freee 未計上）」と「前受金の入金（クラファンなど）」を足し引きする行を足し、最後の行を「全体の結果」にする。この数字はカードの全体と同じになる
- 店舗だけ: 月次レポートの①の内訳（売上の内訳・原価・原価率・費用の科目別・人件費前の利益・人件費・結果）を出す
- イベント: イベントの区分の行を科目ごとにまとめて出す（イベントの名前の一覧と、売上・費用・結果）

## 3. 月次レポート（`/monthly`）

- ③「この月の成績」を `scopes.total` にする。説明文を「店舗とイベントと臨時（クラファンや補助金などの一度きりの収入・支出）を合わせた結果」にする
- 欄外の「前受金」の一覧は、③に含めた旨を書き添える
- それ以外（時間帯別の売上、アルバイトの試算など）は変えない

## やらないこと

- 振り分けの決まりの見直し（どの科目・タグを臨時にするか）
- freee への書き込み
- 店の画面と管理画面の作り直し（別の設計で進める）
- 経理画面以外の画面（売上・分析・経営）の数字の見直し

## 確かめ方

- 純粋な関数のテスト（`node --test`）: 4つの数字の計算（前受金を臨時に足す、全体が3つの和）、表の行の区分の決め方（取引の区分を引く、混ざるときは金額の大きい方、結びつかない行は店舗、付け替えが勝つ）
- 本番で 2026-08・09・10 について、経理画面の4つのカードと月次レポートの4つの数字が一致すること。9月は 店舗 −¥173,121、イベント +¥121,976、臨時 +¥321,479、全体 +¥270,334 になる見込み（2026-10-18 の月次レポートの値からの計算）
