# 経理画面の別レイアウトと、月次のエクセル風の表 設計書

2026-10-15 / 依頼: 坂本さん

## 目的

経理の画面を店舗側とは全く別の見た目にする（ABC English の管理画面のような左のサイドバー）。
月次ページの「経理で見る」を、1行＝1件の入出金のエクセル風の表にして、PCで月のお金の出入りを一覧で確かめられるようにする。
表には絞り込みと印刷、行ごとの色とメモ、月の経理メモ（申し送り）を付ける。

成功の条件:

- 経理の15ページを開くと、店舗側のナビは出ず、左に経理のサイドバーが出る。URLは今のまま
- 月次の「経理で見る」が、入金・カード・銀行・現金・立替・移動で区切られた表になり、区切りごとの小計と、月の合計が出る
- 行に付けた色とメモ、経理メモが、開き直しても残る
- A4横で印刷でき、サイドバーや道具の帯は印刷されない

## 決まったこと（坂本さんの回答）

| 論点 | 決定 |
|---|---|
| 「別のページ」の意味 | 同じサイト（flat-keihi.vercel.app）の中で、経理だけ見た目と入口を別にする。左のサイドバー |
| 表の形 | 1行＝1件の入出金。支払い方法ごとに区切って小計 |
| 表でできること | 絞り込みと印刷、行のメモと色、月の経理メモ（申し送り）、その場で科目・摘要を直して freee に反映 |
| 進め方 | 2回に分ける。今回は freee への反映以外。freee への反映は2回目に別に設計する |
| 端末 | 表はPCで見る。スマホは /ryoshusho の撮影が中心。表はスマホでは横スクロールでよい |
| 作り方 | A案: 経理のページを Next.js のルートグループ `app/(keiri)/` に移し、専用のレイアウトを置く |

## 置いた前提

- ページのURLは変えない（LINEなどで共有したリンクを壊さない）。ルートグループはURLに出ない
- 「会計で見る」（損益計算書）は中身を変えず、新しいレイアウトの中にそのまま置く
- 経理画面では、右下のヘルプのチャット（`HelpWidget`）を出さない
- 色・メモ・経理メモはシステムの KV に保存し、freee には書かない
- 表はライブラリを入れず、今のサイトと同じ書き方（styled-jsx と `globals.css` の色）で作る。月に数百行なので十分

## 1. 画面の外枠（サイドバー）

### ページの移動

次の15ページを `app/(keiri)/` の下に移す（`git mv`。中身は `<Nav />` を外すだけ）。

`keiri`（月次）, `ryoshusho`, `receipts`, `meisai`, `pending`, `kariire`, `payables`, `bills`, `loans`, `items`, `report`, `shorui`, `contracts`, `company`, `zeirishi`

- 各ページの `import Nav` と `<Nav />` を消す（`components/keiri/KeiriMonthly.tsx` も同じ）
- `components/Nav.tsx` から経理用ナビへの差し替え（`isKeiriPath` と `KeiriNav`）を消す。店舗側の「経理 →」（`/keiri`）のリンクは残す
- `components/KeiriNav.tsx` は消す

### レイアウト

- `app/(keiri)/layout.tsx` が `components/keiri/KeiriShell.tsx`（クライアント）でページを包む
- サイドバーは暗い色（`--ink`）にして、店舗側と一目で見分けられるようにする。並びは分野で区切る

```
flat. 経理
 📅 月次
 記録する   🧾 領収書 / 🗂 保存済み領収書 / 🏦 明細 / ⏳ 処理待ち
 支払い     💴 立替 / 💰 払うもの / 🔁 定期請求 / 🏦 借入返済
 集計       🧺 品目台帳 / 📊 用途別
 書類       📄 書類 / 📜 契約書 / 🏢 会社書類 / 🧑‍💼 税理士

```

- 並びと分野は `lib/keiri/nav.ts` の `KEIRI_TABS` に `group` を足して持つ。`/receipts`（保存済み領収書）もタブに入れる（今まではタブに無く、`KEIRI_EXTRA_PATHS` で経理扱いにしていた）
- いま開いているページのタブを目立たせる（`usePathname`）
- 幅 900px 以上（PC）: サイドバーを左に固定（幅 220px）。右側にページを出す。月次は右側の横幅いっぱいを使う。ほかのページは今の自分の幅（`.wrap` など）のまま
- 幅 900px 未満（スマホ）: サイドバーは出さず、上に「☰ 経理 ／ ページ名」の帯を出す。☰ でメニューを上から開き、ページを選ぶか外を押すと閉じる。/ryoshusho の撮影は今まで通り使える
- `HelpWidget` は `isKeiriPath(path)` のとき何も出さない

## 2. 月次の表（経理で見る）

### 並び（上から）

1. 月のタブ: 2026年6月（会計年度の初め・会社設立の月）から今月まで、新しい月が左。今の月に印。押すとその月へ（URLの `month` は今まで通り）
2. 数字のカード: 入金・出金・差引・領収書なし・未処理（今と同じ。月全体の数字で、絞り込みには左右されない）
3. 経理メモ（3章）
4. 道具の帯: 検索（相手・科目・摘要・メモの文字で絞る）、「領収書なしだけ」「未処理だけ」のチェック、印刷、「経理で見る／会計で見る」の切り替え（URLの `view` は今まで通り）
5. 表

「会計で見る」のときは 1（月のタブ）・3（経理メモ）・4 の「経理で見る／会計で見る」の切り替えと `PlTable` を出す。2 の数字のカードは入出金の数字なので、「経理で見る」のときだけ出す（会計で見るのときは月次の API が入出金を返さないため）。

### 列

| 列 | 中身 |
|---|---|
| 日付 | `10/05` の形 |
| 相手 | 取引先があれば取引先、なければ明細の文字（`cleanBankText` 後） |
| 科目 | 紐づく取引・振替伝票の科目。複数は「・」でつなぐ |
| 摘要 | 紐づく取引・振替伝票の摘要。口座振替などは「現金へ移動」「現金の預け入れ」「売上金（PayPayなど・Square経由）」「口座振替」 |
| 入金 | 入金の行だけ。右寄せ |
| 出金 | 出金の行だけ。右寄せ |
| 領収書 | 🧾（押すと画像）／📦 注文（Amazon）／⚠ なし（記録済み）／⚠ なし／空（銀行・移動・入金） |
| freee | ✓（処理済み）／未処理／消込待ち。freee で開くリンク（`freeeLinks`） |
| メモ | 行に付けたメモ（3章） |

- 見出しの行は、下にスクロールしても上に残す（`position: sticky`）
- 金額は桁をそろえる（`tabular-nums`）
- 未処理の行は相手を赤字にする（今と同じ）

### 区切りと小計

- 区切りの順: 入金 → カード → 銀行 → 現金 → 立替 → 移動
  - 入金: `inflows` のうち移動でないもの
  - カード・銀行・現金・立替: `outflows` の `tag`
  - 移動: ATM出金・現金の預け入れ（`kind === "move"`）。薄く出し、合計に入れない
- 区切りごとに見出しの行（色の帯・区切りの名前・件数・小計）。区切りの中は日付順
- 行が0件の区切りは出さない
- 一番下に合計の行: 入金計・出金計・差引（移動を除く）
- 絞り込み中は、区切りの件数・小計・合計の行を絞り込んだ行で計算する（数字のカードは月全体のまま）

### 行を開く

- 行を押すと、すぐ下に詳細の行を開く: 明細の原文、freee で開くリンク、領収書の画像（`ReceiptPreview`）。もう一度押すと閉じる
- 領収書の列の 🧾 を押しても同じように開く

### 印刷

- 道具の帯の「印刷」で `window.print()`
- `@media print`: サイドバー・スマホの帯・道具の帯・経理メモの入力欄・月のタブを隠す。`@page { size: A4 landscape }`。表は横幅いっぱい
- 絞り込みをしているときは、その結果だけが印刷される（画面に出ている行がそのまま出る）

### データの形の変更（`lib/keiri/types.ts` の `CashRow`）

今は「科目／摘要（未処理）」を `detail` の1つの文字にまとめている。表の列に分けるため、`detail` をやめて次の3つにする。

```ts
account: string;      // 科目（複数は「・」）。無ければ ""
description: string;  // 摘要。無ければ ""
status: "done" | "todo" | "waiting"; // freeeで処理済み／未処理／消込待ち
```

- `processed` は `status === "done"` と同じなので消し、`summarize` などは `status` を見る
- 数字のカードの「未処理」と、道具の帯の「未処理だけ」は、`status` が `todo` か `waiting` の行（freee の明細がまだ未処理のもの。今の数え方と同じ）
- 「未処理（freeeでまだ登録していない）」「（未処理）」「（freeeで消込待ち）」の文字は作らない。状態は `status` だけで表す（画面が文字にする）
- どの取引とも突き合わないが freee では処理済みの明細は、`status: "done"`、摘要に「freeeの取引と突き合わせできませんでした」
- `linkReceipts.ts` の Amazon の注文番号は `description` から探す
- 今のカード型の一覧 `components/keiri/CashTable.tsx` は消し、表 `components/keiri/KeiriSheet.tsx` に置き換える

## 3. 行の色とメモ、経理メモ

### 行の色とメモ

- 行を右クリック、またはメモの列のセルを押すと、小さなメニューを開く: 色（なし・黄・桃・水・緑・橙）とメモの入力、「保存」
- 色は行の背景に、メモはメモの列に出す
- 保存先: KV のキー `keiri:marks:{YYYY-MM}` に `{ [行のkey]: { color?: string; note?: string; updatedAt: string } }`。色もメモも空にしたら、その行の分を消す
- 行の key（`w{明細ID}`・`d{取引ID}-p{番号}`・`j{伝票ID}-c{番号}`・`cash-{日付}`）で引く。freee 側で取引が消えるなどして行が無くなったときは、その印は出さない（残っていても害はない）

### 経理メモ（申し送り）

- 表の上に、入力欄（「例）8/19のAmazonは2回払い。領収書は1枚」）と「追加」、その下に一覧
- 書いた月から、「済み」にするまで、次の月以降にも出る
- 済みにすると、書いた月にだけ取り消し線つきで残り、次の月以降には出ない
- 各メモに「済み」（取り消しは「戻す」）と「削除」
- 保存先: KV のキー `keiri:memos` に一覧 `{ id, month, text, done, createdAt, doneAt? }[]`

### API

freee の読み込みを待たずに保存できるよう、月次のAPIとは分ける。

| API | 中身 |
|---|---|
| `GET /api/keiri/marks?month=YYYY-MM` | その月の行の色とメモ |
| `PUT /api/keiri/marks` | `{ month, key, color?, note? }` を保存（両方空なら消す） |
| `GET /api/keiri/memos?month=YYYY-MM` | その月に出す経理メモ |
| `POST /api/keiri/memos` | `{ month, text }` を足す |
| `PATCH /api/keiri/memos` | `{ id, done }` で済み／戻す |
| `DELETE /api/keiri/memos?id=` | 消す |

- 合言葉（`SITE_PASSWORD`）の確認は、今のミドルウェアのまま
- KV の読み書きは `lib/keiri/store.ts` に置く（`lib/pending-expenses.ts` と同じ `@vercel/kv` の作り方）

## このあとの流れ（今回の範囲の外。それぞれ別に設計する）

坂本さんは、ゆくゆくはこの経理を他の会社にも使ってもらいたい。他社に入れてもらうときの売りは「届いた請求書・郵便物・契約書・領収書を写真で撮るだけで、データベースになって、システムの中で承認ボタンを押せばそのまま freee に登録される」こと。2026-10-15 に「一旦 flat でやろう」と決めたので、まず flat-keihi の中で部品ごとに作る。

1. **経理の画面**（この設計書）: サイドバーと月次の表
2. **書類を撮る → データベース → 承認で freee 登録**: 請求書・郵便物・契約書・領収書を撮ると、AI が種類を見分けて中身（取引先・金額・日付・支払期限・契約期間など）を取り出し、台帳に入れる。承認ボタンで freee に登録する（請求書は未払いの取引、領収書は支払い済みの取引。画像も添付）。今の /ryoshusho・/receipts・/shorui・/contracts・/company をまとめ直す
3. **仕訳と品目を先に決めておくページ**: 2 の自動判別の元になる。今は freee の科目の割り当てがコードの中にある
4. **固定費を毎月見るページ**: 電気・水道・ネット・家賃などを月ごとに並べる。今の /bills を広げる
5. **表から科目・摘要を直して freee に反映**

他社向けにするときに効く freee の決まり（[アプリについて](https://developer.freee.co.jp/reference/application-types)、2026-10-15 確認）:

- プライベートアプリは5事業所まで。パブリックアプリは最初20事業所まで（ストア掲載か審査で外れる）で、銀行明細の取得には申請が要る
- アプリの種類は後から変えられない。他社向けにはパブリックアプリを新しく作る
- 認可URLに `prompt=select_company` を付けると、事業所ごとにトークンを出せる（ワンクリック連携の土台）
