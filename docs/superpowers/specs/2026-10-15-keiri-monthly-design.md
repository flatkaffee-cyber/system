# 経理画面の切り離しと月次ページ 設計書

2026-10-15 / 依頼: 坂本さん

## 目的

経理の作業と数字の確認を、店舗運営の画面から切り離した専用の画面で行う。
その画面の中心に「月ごとのお金の出入り」と「月ごとの損益」を1ページで見られる月次ページを置く。

成功の条件:

- 店舗側のナビから経理が消え、「経理 →」から専用画面に入れる
- 月次ページで月を前後に移動でき、「経理で見る」「会計で見る」を切り替えられる
- 「会計で見る」の合計が freee の試算表（同じ月）と一致する
- 「経理で見る」で、カード払いごとに紐づく領収書を開ける。領収書が無いものは一目で分かる

## 決まったこと（坂本さんの回答）

| 論点 | 決定 |
|---|---|
| 経理タブの扱い | 店舗側から完全に切り離した別画面にする |
| 見られる人 | 入口を分けるだけ。合言葉は今の共通のもの（`SITE_PASSWORD`）のまま |
| 税金 | 見込み額を出す |
| 既存の「月次レポート」「経営」 | そのまま残す。今回は触らない |
| 数字の取り方 | 合計は freee の試算表、明細は取引・振替伝票・口座明細から取る |
| 月次の見方 | 「経理で見る」と「会計で見る」を切り替えられるようにする |

## 置いた前提

- 「コスト（売上原価）」は試算表の売上原価（仕入高）。それ以外の出費は販管費として扱う
- 「人件費」は 給料手当・雑給・法定福利費 の合計。役員報酬は別の行に出す。どちらも販管費に含まれているので、利益の計算で二重に引かない
- 支払い方法のタグは「カード」「銀行」「現金」に「立替」（坂本さんの立替＝役員借入金）を加えた4つ
- 会計年度は 6/1〜翌5/31。freee の `fiscal_year` は期首の年（2026年10月 → 2026）。事業所情報から取るのではなく、6月始まりの固定ルールで決める（期首が変わったら1か所直す）

## 画面

### 入り口とナビ（`components/Nav.tsx`）

- `GROUPS` から `keiri` を外し、`KEIRI_TABS` として別に持つ
- 店舗側のナビの右端に「経理 →」リンク（`/keiri`）を置く
- いま開いているページが `KEIRI_TABS` に含まれるときは、店舗側のナビの代わりに経理用のナビを出す
  - 並び: 📅 月次（`/keiri`）／🧾 領収書（`/`）／🏦 明細／⏳ 処理待ち／💴 立替／💰 払うもの／🔁 定期請求／🏦 借入返済／🧺 品目台帳／📊 用途別／📄 書類／📜 契約書／🏢 会社書類／🧑‍💼 税理士
  - 左端に「← 店舗へ」（`/table`）
  - 色を少し変えて、経理画面にいることが分かるようにする
- 既存ページのURLは変えない。各ページは今まで通り `<Nav />` を置くだけで、Nav の中で出し分ける
- 店舗側のナビで前回選んだ分野が `keiri` として保存されていた場合は、`tenpo`（店舗運営）として扱う

### 月次ページ（`/keiri?month=2026-10`）

上部は共通:

```
‹ 9月 │ 2026年10月 │ 11月 ›          [経理で見る] [会計で見る]
```

- 月の初期値は今月（JST）。見方の初期値は「経理で見る」
- 月と見方はURLのクエリ（`month`, `view`）に持つ。ブラウザの戻るで前の月に戻れる

#### 経理で見る（お金の出入り・日付順）

```
入金 ¥xxx   出金 ¥xxx   差引 ¥xxx   領収書なし n件   未処理 n件

── 入ってきたお金 ──
10/02  Square振込     ¥15,286   売上金
10/02  PayPay振込     ¥140,669  売上金
10/12  町田創          ¥50,000   その他（役員貸付金の返済）

── 出ていったお金 ──
10/01 [カード] AMAZON CO JP      ¥30,380  ⚠領収書なし
10/02 [銀行]   日本セーフティー   ¥108,130 地代家賃・支払手数料
10/11 [現金]   CAINZ 彦根店       ¥2,378   🧾
```

入ってきたお金:

- 普通預金の入金明細（`wallet_txns`, `entry_side=income`）
- 現金売上（Square連携の売上取引のうち、支払元が「現金」口座の分を日ごとに合計）
- 区分は紐づく取引・振替で決める。売上高・売掛金・Squareその他からの振替は「売上金」、それ以外は「その他」とし、科目名を添える

出ていったお金:

| タグ | 元データ |
|---|---|
| カード | 普通預金の出金明細のうち、摘要が `Visaデビット利用` で始まるもの |
| 銀行 | 普通預金の出金明細のうち、上記以外（振込・引き落とし） |
| 現金 | 支払元が「現金」口座の支出取引（Square連携の売上取引は除く）、貸方が「現金」の振替伝票 |
| 立替 | 貸方が「役員借入金」の振替伝票（領収書の立替登録） |

- ATM出金（普通預金→現金の口座振替）は、出金の合計には入れない。一覧には薄く「現金へ移動」と出す
- 各行は、紐づく freee の取引から科目と摘要を出す。未処理の明細は「未処理」と出す
- 領収書との紐づけ: システムの領収書の `registered.journalId` が、その行の取引IDまたは振替伝票IDと一致するもの。押すと領収書画像（既存の `/api/receipts/image`）を開く
- 領収書が無いカード・銀行の行のうち、「レシートなし経費」（`pending-expenses`）に同じ日付・金額で載っているものは「⚠領収書なし（記録済み）」と出す。載っていないものは「⚠領収書なし」と出す
- 行を押すと、科目・摘要・取引ID・freeeで開くリンクが開く

明細と取引の紐づけ:

- freee のAPIは、明細と取引の対応を直接返さない
- 取引の `payments`（支払元の口座・日付・金額）と、明細（口座・日付・金額）を突き合わせる
- 同じ日付・金額の候補が複数あるときは、1件ずつ先に見つかった方に割り当てる（1つの支払いを2つの明細に使わない）

#### 会計で見る（損益計算書の形）

```
売上高                     ¥xxx
  売上原価                 ¥xxx
売上総利益（粗利）         ¥xxx   粗利率 xx%
  販売費及び一般管理費     ¥xxx   ▸
    うち 役員報酬          ¥xxx
    うち 人件費            ¥xxx
営業利益                   ¥xxx
  営業外収益               ¥xxx   ▸
  営業外費用               ¥xxx   ▸
経常利益                   ¥xxx
  特別利益                 ¥xxx
  特別損失                 ¥xxx
税引前当期純利益           ¥xxx
  法人税等（見込み）       ¥xxx
当期純利益（見込み）       ¥xxx
```

- 数字は freee の `GET /api/1/reports/trial_pl`（`fiscal_year`, `start_month=end_month=対象月`, `account_item_display_type=group`）から取る
- その月の金額 = `closing_balance − opening_balance`。収益・費用・各利益の行のどれも、この式でその月の増減になる（利益の行は黒字がプラス）
- ▸ を開くと勘定科目ごとの金額。さらに科目を開くと、その月の仕訳（取引の明細行・振替伝票の行）を日付順に出す
- 法人税等（見込み） = 税引前当期純利益がプラスなら × 25%（中小法人の目安）。どの月も均等割 5,833円（年7万円÷12）を足す。帳簿に法人税等の計上があれば、その月は見込みではなく帳簿の額を出す
- 「当期純利益（見込み）」 = 税引前当期純利益 − 法人税等（見込み）

## データの流れ

```
/keiri（画面）
  └ GET /api/keiri/monthly?month=YYYY-MM&view=cash|pl
       ├ lib/keiri/period.ts      月 → 期間・fiscal_year
       ├ lib/keiri/pl.ts          trial_pl → 損益の行、税金の見込み、科目ごとの仕訳
       ├ lib/keiri/cashflow.ts    明細・取引・振替伝票・振替 → 入出金の行
       └ lib/keiri/linkReceipts.ts 行 ↔ 領収書・レシートなし経費
```

- freee の取得には既存の `lib/freee.ts`（`freeeGet`）を使う。ページングは `lib/monthlyReport.ts` と同じく `limit=100` で最後まで取る
- 1回の表示で呼ぶ freee API: 試算表1、取引1〜3、振替伝票1〜2、口座明細1〜2、口座振替1。キャッシュは持たない（今日の登録がすぐ見えるのを優先）
- `view=pl` のときは試算表と、科目ごとの仕訳に要る取引・振替伝票だけを取る。`view=cash` のときは口座明細・取引・振替伝票・振替と、領収書を取る
- `period.ts` / `pl.ts` / `cashflow.ts` / `linkReceipts.ts` は、freee から取ったデータを受け取って行を返す純粋な関数にする（API呼び出しは route 側）

## エラーのとき

- freee 未接続: 既存ページと同じ「freee未接続です」を出し、接続ページへのリンクを置く
- 試算表が取れない（`up_to_date=false` を含む）: 数字の上に「freeeの集計が更新中です」と出す。取れた分は表示する
- 経理で見るの一部（領収書の取得など）が失敗: その部分だけ「読み込めませんでした」と出し、ほかの行は出す
- 未来の月: 「まだデータがありません」

## 確認の方法

- 純粋な関数（`period.ts`, `pl.ts`, `cashflow.ts`, `linkReceipts.ts`）に `node --test` で動くテストを付ける。テスト用の入力は、2026年9月の試算表と10月の明細を小さく切り出したもの
  - 9月の試算表から: 売上高 713,513 円、役員報酬 188,997 円、税引前当期純利益 −153,545 円 が出ること
  - 明細と取引の突き合わせで、同じ日付・金額の候補が2つあっても二重に割り当てないこと
  - ATM出金が出金合計に入らないこと
- `npm run build` が通ること
- 本番（flat-keihi.vercel.app）で、2026年9月・10月を開いて、会計で見るの各合計が freee の試算表と一致することを目で確認する
