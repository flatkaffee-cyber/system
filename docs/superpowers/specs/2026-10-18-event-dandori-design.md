# 出店イベントの段取り表（AIが組む）設計

2026-10-18 坂本さんと相談して決めた内容。

## なぜ作るか

2026-10-12 のひこねいろ文化祭（荒神山）で、ワッフルの仕込みを前日の夜に始めてしまい、深夜まで焼き続けた。仕込みを「いつ・誰が・どれだけ」やるかが事前に決まっていなかったのが原因。

これからは出店イベントごとに、**前々日の仕込みから当日の撤収までを、誰が何時に何をするかの1本の表**にして、スタッフ全員がスマホで見られる・紙でも持てる状態にしたい。しかも毎回ゼロから考えるのではなく、**過去の反省（ノウハウ）を覚えたAIが、イベントの資料と「何を何枚売るか・誰が入るか」から組んでくれる**ようにしたい。

見本：滋大祭（10/24・25）の段取り表を手で作ったもの → `flat-cafe/tmp-docs/滋大祭_段取り表_1024-25.html`（PDFも同じ場所）。機能の出力はこれと同じ形・同じ粒度を目指す。

## 使う人と使う場面

- 作る人：主に坂本。イベントが決まったら資料を上げて、チャットで条件を伝える
- 見る人：スタッフ全員（坂本・町田・櫻井・國仲・バイト）。**スマホでシステムの「イベント」タブから見る**。紙にも**印刷**して持つ
- 場面：前々日〜当日。当日はテントの中で「次に何をするか」を確認する

## やること（ゴール）

1. イベントごとに段取り表を作れる。イベントは既存の「出店準備」（`/shutten`、`lib/shutten.ts` の `ShuttenEvent`）と同じものを使い、1つのイベントに持ち物リストと段取り表がぶら下がる
2. **資料をアップロード**できる（PDF・写真。主催者のマニュアル、配置図、搬入案内など）
3. **チャットで条件を伝える**と、AIが資料・ノウハウ・店のシフトを合わせて段取り表を作る
   - 伝える例：売る品目と枚数、誰がイベントに出て誰が店に残るか、交代は半分ずつ、仕込みは前日に全部、など
4. AIが作った表を、**チャットで直せる**（「町田のワッフルを15:00からに」など）。最後は人が見て確定する
5. **店のシフトはシフトタブ（`lib/shift.ts` の `getShifts()`）から自動で取り込む**。表の灰色の欄になる
   - **シフトタブが正**（2026-10-19 坂本さん決定）。イベント日の交代（例：滋大祭24日の13:45交代）もシフトタブに入れてもらう。AIは店のシフトを書き換えず、空いている時間だけでイベント側の段取りを組む
   - イベントの作業と店のシフトで**同じ人の時間がぶつかったら、表の上に警告を出す**
   - 表を開くたびにシフトタブを読み直す（作った時点で固定しない）。シフトが変わって段取りとぶつかるようになったら、同じく警告を出す
6. 段取り表に出てくる「やること」は、同じイベントの**チェックリストにも入る**（今の持ち物リストと同じ画面で確認できる）
7. **ノウハウのメモ**をAIが毎回読む。メモは画面から足したり直したりできる

## 段取り表の形（坂本さんが決めた）

- **前々日から当日（連日なら最終日）までを1本の長い表**にする。日の区切りは帯（イベントの色）で入れる
- **横＝スタッフの名前、縦＝時間、セル＝その人がやること**
- セルは種類で色分けする：店のシフト（灰）／仕込み・準備（橙）／移動・搬入・撤収（紫）／販売（緑）
- **どの色のセルでも文字は濃い色で固定**（ブラウザが暗い表示でも読めること。見本作りの最中に、暗い表示で文字が読めなくなった）
- 何もない時間帯は詰める。時間は行ごとに書く（30分刻みの格子にはしない。見本と同じ「出来事の時刻ごとに1行」）
- 全員にかかる行（「全員で持ち物チェック」など）は横につなげてよい
- 表の下に、仕込み数（日ごとの内訳）・出店セット・主催者の決まり・連絡先をカードで並べる（見本と同じ）
- 印刷はA4横。日が変わるところで改ページ（前々日と前日は1ページにまとめてよい）

## ノウハウ（最初に入れておく中身）

AIは段取りを組むとき、必ずこれを前提にする。

- ワッフル：前日の**昼過ぎから人を入れ、約3時間で生地の仕込み→焼き**まで終える。夜に始めない。**2枚焼くのに最低6分**。当日は電源タップがあれば温めて出し、なければそのまま出す
- ホットサンド：**前々日にたね（具）**、**前日に指定枚数を組み立てて保冷バッグへ**。会場で焼く。連日イベントでも前日に全部組み立てる（滋大祭で決定）。2日目の分は店の冷蔵庫に置いておく
- **出店セット**：前日に容器へワッフルシュガー・バーガー紙・チョコソース・ホットサンドのプレート等を詰める
- 前日までに**現金小口**を作る
- 前日の終わりに**全員で持ち物チェック**（出店準備のリスト）
- イベントでは**お金を触る係と食品を触る係を分ける**
- 連日イベントの1日目の撤収後は、店で翌日の準備（出店セットの補充・現金小口の確認など）
- 売値の基本：ホットサンド900円、ワッフル500円、ドリンク500円
- 過去の実績：荒神山 10/12（5時間）でホットサンド クラシック約36・ツナ約25、ワッフル約31、ドリンク約14、会計 キャッシュレス約22・現金約37

## 決まっていない・作る人に任せること

- 画面の置き場所と名前。案：`/shutten` の中にタブ（持ち物／段取り表／資料）を足す、または `/shutten/dandori`。「イベント」の分野のナビに入れること
- AIの出力の形（構造化データにして画面で表に描く想定。JSONの形は任せる）
- チャットの履歴をどこまで残すか
- 資料の保存先は `lib/fileStore.ts`（Blob）を使う。AIへの渡し方（PDFは document、写真は image）は `app/api/bills/extract/route.ts` と同じやり方でよい
- AIのモデルは既存のAPIと同じもの（`claude-opus-4-8`）でよい
- スタッフの列はシフトの `STAFF`（坂本・町田・櫻井・バイト）を基本に、イベントに出る人だけでも可。國仲など足せるようにする

## 作る側で決めたこと（Claudeの判断。2026-10-19 坂本さんが「進めて」で了承）

- **直し方**：チャットで直すのが基本。画面のセルを直接書き換えることもできる。AIには毎回「今の表」を渡し、言われたところ以外は変えないよう指示する。保存のたびに版を残し、**1つ前の版に戻せる**。「確定」したらAIは書き換えない（解除すれば直せる）
- **チェックリスト**：持ち物リストと同じ画面に「やること」として別に並べる（持ち物と混ぜない）。各項目に日付・時刻・担当を持たせる。表を作り直しても、同じ日・同じ担当・同じ内容の項目はidを引き継ぎ、チェック済みが消えないようにする。表から消えた作業はチェックリストからも消す
- **スマホ**：見本と同じBの形で、**時刻の列を固定して横にスクロール**する。名前ごとの縦の画面は作らない（相談の中でCの「自分の分だけ表示」ではなくBが選ばれたため）
- **表の下のカード**（仕込み数・出店セット・決まり・連絡先）は、AIが表と一緒に1つの出力として出す。仕込み数は表の中の数字と合うようにAIに確かめさせる

## やらないこと

- Squareや出店レジ（`/shutten/reji`）との連動はしない（今回は段取りだけ）
- 保健所・消防などの届出の管理はしない（坂本さんが自分で対応している）
- シフトタブへの書き戻しはしない（読むだけ）

## これは失敗、というもの

- AIが組んだ表が、ノウハウを無視している（例：ワッフルを前日の夜にしている）
- 店のシフトとぶつかっているのに気づけない（イベントに出ている人が同じ時間に店の欄にもいる）
- スマホで横に見切れて読めない、印刷で文字が小さすぎて読めない
- 直すたびに全部作り直しになり、前に直したところが消える
